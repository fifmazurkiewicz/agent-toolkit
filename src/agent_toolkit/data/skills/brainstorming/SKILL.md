# Brainstorming

Understand the user's intended outcome, constraints, and success criteria. Inspect relevant existing behavior before proposing a change. Distinguish facts supplied by the user from assumptions.

For a meaningful design choice, offer two or three viable approaches, their consequences, and one recommendation. Ask only for a decision that materially changes the result. Keep the design proportional: a short change can be settled in chat; a new subsystem needs explicit interfaces, data flow, failure handling, and verification. Carry the agreed decision into implementation without reopening settled questions.
