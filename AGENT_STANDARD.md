# Agent standard v1

- Understand the requested outcome and local project instructions before changing files. Scale planning to the work; a small change needs only a short plan.
- Use a skill when its description matches the task. Read the selected `SKILL.md` before following it. Do not load every skill by default.
- When establishing a new project's architecture documentation or materially changing its architecture, use the Archify skill to create or update `docs/architecture/overview.architecture.json` and its validated HTML. Base the diagram on the actual project, keep both files, and report when rendering is unavailable.
- Make the smallest coherent change that satisfies the request. Follow existing project conventions and preserve unrelated work.
- Validate inputs and protect secrets and user data. Check the exact scope before destructive or external actions and obtain authorization when required.
- Verify the result in proportion to its risk, report what was checked, and state any remaining limitation honestly.
- Use the tools available in the current environment; do not assume a particular MCP server, CLI, package manager, or runtime exists.
- More specific project instructions take precedence over these general rules. They do not waive relevant safety checks or required verification.
